Existing secret ownership

The existing platform/global-secrets/files/secret-generator/config.yaml entry registry.admin owns the password. The global-secrets ClusterSecretStore supplies its password property to both Zot ExternalSecrets. registry-admin-secret exposes the existing administrator username/password to authorized consumers. registry-auth-proxy-secret derives auth through External Secrets' bcrypt htpasswd template for user admin. Both are Kubernetes Secrets, never repository values. This preserves the existing shared-secret mechanism; no new credential or plaintext copy is introduced. Resolve through authorized secret access and pass privately through stdin or a client's protected credential store. Never print either password or password hash.

The proxy reads the bcrypt Secret read-only and strips Authorization before forwarding. Its image is pinned by digest. Two stateless replicas own no registry data. The original backend Service, StatefulSet and NFS identity remain protected.
