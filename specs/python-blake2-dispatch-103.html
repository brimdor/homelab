Issue 103: Python BLAKE2 dispatch repair

Status: software prerequisite open. This qualification does not install a replacement or claim vendor support for a local backport.

Cause and evidence

Sprigatito runs the original verified python3-libs-3.14.8-1.fc44 package. BLAKE2b raises SIGILL at extension offset 0x6bd0, a vpxor instruction, while BLAKE2s, SHA-256, zlib and SELinux bindings pass. Native probe ezmqe6jw at 2026-10-29 14:31 UTC found raw CPUID AVX=1 but GCC runtime AVX=0 and AVX2=0. GDS mitigation remains AVX disabled, no microcode. The exact Fedora source archive confirms BLAKE2 checks only raw CPUID. The kernel documentation describes this failure when userspace omits the XSAVE YMM check. Fedora repositories currently offer the same installed build; no fixed vendor package is claimed.

Smallest repair candidate

On this GCC x86_64 path, use the documented GCC runtime CPU feature detection for AVX and AVX2. Preserve all HACL algorithms, SIMD implementations, public API and non-GCC branches. Keep GDS mitigation, SELinux Enforcing, seccomp, image identities, NAS protections and application processes unchanged. This is a repository-owned backport, not an upstream release.

Qualify the candidate without installing it. Download the official CPython 3.14.8 source, require the archive and module hashes independently captured from Fedora's exact source RPM, download only the matching signed Fedora development RPM, verify its pinned hash and native signature, and extract its headers privately without installing packages. Build only the five BLAKE2 compilation units, sequentially at nice 19, with the matching Fedora ABI and the original separately compiled SIMD flags. Compare 72 independent local Python reference vectors, including empty and large input, keying, salt, personalization, tree parameters, streaming and copying, in a core-disabled fresh child. Require the installed extension hash unchanged. Remove every owned downloaded/build/test file in finally.

Installation gate and rollback design

Installation remains unimplemented until qualification passes. A later published workflow must preserve the exact original extension, owner, mode and SELinux attributes in protected non-NAS recovery storage, serialize with maintenance ownership and package actors, enforce original package/hash identity, and atomically replace only that extension. Any post-install vector or Ansible acceptance failure must atomically restore the original and verify its hash and metadata. Verify normal Ansible fact gathering and idempotent GPU policy execution, then actual node, Ceph and application behavior. A future vendor package change invalidates this exact backport identity and requires review; do not silently overlay it.
