Finding and scope

Execution and acceptance

  1. Bind both hosts to exact machine IDs and root UUIDs. Require private local ext4 recovery roots and no mounted, open, or mapped consumers of each point.
  2. Check every payload against its original verified manifest. Publish the exact content and metadata fingerprints in metal/maintenance/recovery-relocation-103-20261101.json with the migration code on canonical Gitea master before copying.
  3. Stream each point through SSH pipes in workstation RAM. Preserve every file, directory, permission, owner, nanosecond modification time, and extended attribute. Keep partial copies and the original source on failure.
  4. Flush destination files and directories. Independently reopen and hash the complete receiver tree. Require exact content and metadata equality before committing a source relocation.
  5. Write and flush the durable source location record before the first source unlink. Recheck every source file before unlinking. Leave relocated.json at the original point path. On Growlithe, append -relocated-20261101 to each point name, preserving all preexisting receiver backups. Old local readers fail closed; do not replace this record with a symlink.
  6. Reopen the protected receiver after relocation. Verify actual capacity and kubelet pressure clearance. Recheck Arcanine's unchanged source binary, boot, ownership, and original journals before any unstarted initialization continuation.

Capacity prevention

Recovery receipt and restore-copy guards preserve the verified 80% image-GC low threshold, accounting for three recovery payload copies. K3s configuration transfer also preserves that threshold before allocating its bounded archive. These are receiver filesystem checks, not workstation testing quotas.

Rollback and interrupted execution

Before source retirement, discard nothing: leave the original and inspect the exact partial destination. After retirement, use the durable location record to recover directly from Growlithe. If a future operator needs the original Pikachu location restored, first qualify capacity and perform the same complete verified copy in reverse; keep Growlithe's protected copy until independent source readback passes. Do not blindly replay an interrupted copy or partially completed source retirement.

Evidence and limits

The exact point manifest checksums, complete tree fingerprints, host identities and byte counts are machine-readable in the repository plan. Local synthetic tests cover tampering, links, permissions, invalid receiver receipts, and receiver capacity. Native Linux transfer and independent readback must prove extended attribute preservation. A successful relocation does not establish whole-homelab GREEN or resolve the separate Bulbasaur I/O finding.
