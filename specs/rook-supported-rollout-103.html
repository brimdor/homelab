Supported fix for the earlier manager gate

Rook's Ceph upgrade guide recommends Ceph 20.2.4 and disabling its optional rook manager module because of manager stability defects. The module serves selected dashboard orchestration pages; Rook's Kubernetes operator remains the storage reconciler. Use mgr.modules: [{name: rook, enabled: false}], record the dashboard limitation and verify all required storage functions. Do not force-enable the defective module or wait indefinitely for an unreleased version. This replaces the earlier enabled-module preservation assumption in the historical qualification documents.

Sources and limits

Rook's versioned upgrade guide supports the adjacent 1.20-to-1.21 transition, requires Kubernetes 1.32 or newer, and orders operator, drivers, then cluster charts. The drivers guide requires Rook-compatible names and image-set configuration. The new chart explicitly assigns normalized driver-name service accounts, so preserve storage driver identities while adopting those accounts.

Versioned CephX guidance requires corrected Rook/Ceph releases and distinguishes core keys, client keys and service tickets. Determine actual generations instead of copying an example value. Kernel support alone does not prove migrated client behavior.
