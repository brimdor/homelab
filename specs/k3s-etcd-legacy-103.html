Evidence and objective

The etcd 3.6 upgrade guide requires a prior 3.5 update and a legacy-data check. The K3s maintainer clarification describes the packaged 3.5.26 transition and unchanged-member upgrades; it does not prove this cluster's complete membership history. The official checker source checks WAL and legacy snapshots, can return without reading WAL when its directory is absent, and can rename invalid snapshot files. Require complete nonempty WAL and snap/db, and run the pinned checker only on an isolated disposable copy.

Before stopping one server, bind a scoped authenticated API reader to a healthy surviving server, retaining the canonical CA and credentials. Observe the exact two surviving voters only during the owned stopped interval; ordinary acceptance still requires all three original member IDs, their existing cluster ID, healthy endpoints and no alarms.

Record a one-shot stop intent; stop only the existing SOURCE K3s unit with KillMode=process. Prove inactive unit, MainPID zero, no 2379 listener and no independent etcd process. Stream the complete stable member tree to a new protected private ext4 point on an existing trusted different host. Verify the source before and after transfer and fsync the receiver.
