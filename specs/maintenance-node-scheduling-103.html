Contract and plan

  1. Build an exact reviewed plan from the current nondeleting v1 Node and current ownership. Accept only a previously schedulable Node for cordon. Bind step, name, UID, resourceVersion, source boolean and target boolean. Missing spec.unschedulable means false; any nonboolean value refuses.
  2. For restore_scheduling, require the caller's original validated cordon plan, same owner Node/UID and its digest equal to the actual first cordon intent. Bind that digest into the restoration plan. An already cordoned original target never becomes schedulable through this component.
  3. Dispatch through the actual ordered hop journal. Persist intent before one patch. Recheck unchanged owners, idle actors, exact reviewed Node version/state and current prerequisite callback while serialized. Use only test UID, test resourceVersion and add spec.unschedulable. Do not retry a failed, rejected or lost-response mutation.
  4. A fresh observer with the exact plan may inspect a pending intent. If the desired boolean is absent, retain pending without a patch. If present, independently verify current prerequisites and exact Node snapshot during journal acceptance, then bind Node identity/version, scheduling state and prerequisite digest in the receipt. Missing, foreign, deleting or changed identities refuse. A response-loss observer never dispatches.
  5. Leave global Kured ownership and native actor hold intact. This component cannot accept applications, release either owner, reboot, execute packages, drain, or access NAS. Callbacks are explicit boundaries, not evidence of real protected recovery, Ceph quorum or application behavior.
