Loki successor maintenance

Maintenance #103, LOKI_SUCCESSOR. Replace EOL Promtail first, preserving the existing Loki 2.6.1 process, emptyDir store, schema v11 and historical indexes. The separate Loki server/chart migration remains open until consistent recovery, schema transitions and restore validation are proved. Do not restart Loki as a side effect of this collector change.

Collector contract and design

Current Promtail 3.5.1 DaemonSet covers seven nodes. Capture all seven legacy position-file hashes, file counts and offsets, recent node ingestion and a fixed historical query with timestamp/content hashes. Convert the current configuration with the verified official Alloy v1.20.1 binary. Review every relabeling rule, CRI stage, discovery node filter, label and destination. Do not bypass conversion errors. The converted file is owned here; no runtime conversion or remote config.

Keep the existing DaemonSet name, immutable selector, service account, RBAC, metrics port, security context, tolerations and mounted log paths. Disable only the dependency's DaemonSet template and replace it in this chart using the same pod helper. Roll one existing Pod at a time with no surge. Graceful Promtail shutdown records its final positions before Alloy starts on that node. Alloy reads the legacy file read-only and saves its own positions under /run/alloy-loki. Existing logs and legacy positions are never deleted. The pinned image is v1.20.1 at digest sha256:2aa2099af76c0098d4af7a4d6e48f86cb66dc1a000222ad927a1c67c6542d13f. This phase preserves existing seven-node coverage; dedicated-worker expansion requires its own reviewed scope.

Validation and rollout

  1. Run an isolated synthetic file test with the exact official native binary: skip the already-read prefix, read the suffix, stop gracefully, append another line, restart with retained Alloy state and prove no prefix or suffix replay. Verify legacy positions unchanged; reap both processes and remove scratch.
  2. Lint/render old and new charts. Assert every resource outside the collector DaemonSet and new ConfigMap is identical. Inspect selector equality, read-only legacy paths, writable separate state, one-at-a-time rollout and exact config. Run scoped pre-commit and diff checks before commit/push.
  3. Refresh Argo; verify the intended revision and all seven new collectors Ready with the exact image digest. Verify legacy position initialization, persistent Alloy offsets, no sustained push/discovery errors, the same seven node labels, new ingestion and the unchanged historical query hashes. Prove Loki Pod UID, restart count and controller template unchanged.

Rollback and limits

Revert the collector commit through Git and Argo to restore Promtail. Its preserved legacy positions can replay the interval collected by Alloy, so rollback has an explicitly bounded duplicate risk. Keep both position stores; do not overwrite either or discard historical indexes. No concurrent old/new collectors on a node and no claim of exactly-once delivery. Existing local log retention bounds recovery if a node or kubelet deletes source files during an outage.

No NAS writes, account changes, notifications or synthetic production logs. The local test uses only synthetic files. This collector step does not complete LOKI_SUCCESSOR or prove durable/offsite Loki recovery.
