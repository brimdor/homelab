Argo CD Redis metrics repair

Maintenance #103, ARGO_REDIS_METRICS, parent OBSERVABILITY.

Objective and baseline

Restore the existing Redis metrics Service and ServiceMonitor. Chart 9.5.18 separately defaults redis.exporter.enabled=false, while the repository enables metrics discovery. The live Pod has no named metrics port; port 9121 refuses connections. Redis is an ephemeral Argo cache: no persistent volume, snapshots disabled and append-only persistence disabled.

Structure and style

Enable the chart's exporter in system/argocd/values.yaml. Preserve the Redis image, password reference, Service, ServiceMonitor, network policies and chart versions. Use nested YAML:

redis:
  exporter:
    enabled: true
  metrics: *metrics

Pin the installed chart's exporter version v1.84.0 to verified GHCR index digest sha256:7ef8e9c26638158fa4e7ad60df8c7e53d1919986753d6c1d2d1876b6ec38d87b. The chart supplies its existing Redis Secret reference to the exporter without exposing the value. Official exporter release.

Plan, commands and acceptance

  1. Inspect the exact chart template and registry manifest. Record current Deployment/Pod identities and cache storage.
  2. Render and lint an isolated chart copy. Require only the Redis Deployment to change, adding one metrics container with named port 9121 and the existing Secret reference. Require the original Redis container and all other objects to remain identical.
  3. Run scoped pre-commit, commit/push canonical Gitea master, immediately refresh Argo and wait for health.
  4. Prove both Redis Pod containers ready, exporter redis_up 1, successful Prometheus scrape, allowed Argo cache/RPC traffic, independent reconciliation and public health. Retain original CORE findings.

Boundaries and rollback

Always preserve unrelated edits, inspect the rendered diff and apply through repository-owned GitOps. The existing Redis cache Pod rolls; no durable database migration or backup restore is involved. Separate approval gates still apply to changes outside this task. Never print credentials, change persistence, disable the NetworkPolicy fix, edit live resources or trigger unrelated application writes.

If acceptance fails, record the exact condition. Revert the exact exporter commit, validate, push master and verify Argo recovery. Do not replace Git recovery with manual Helm or live edits. Whole maintenance remains open until its other tasks and six-layer gates pass.
