Issue 103: maintained PostgreSQL qualification

Status: implementation preparation. No production image change and no acceptance claim.

Scope and choice

BITNAMI_LEGACY requires maintained Gitea database images and safe recovery. The existing PR 115 proposal uses PostgreSQL 17. This candidate instead replaces frozen 16.6 with official maintained 16.15 on Debian 12. PostgreSQL 16 remains supported through November 9, 2028. Staying in major version 16 preserves its documented on-disk compatibility and avoids an unnecessary major-format migration. The exact original task requires evaluation of version 17, not mandatory adoption of version 17.

Backup continuity

The maintained source uses a distinct version 2 guarded manifest, bound to its exact digest, existing PVC/PV/controller and HBA identities. Legacy version 1 provenance remains strict. Capture permits only the idle capture-only guard, verifies all eight public runtime overlay files, clean native control metadata, CSI inode and process/lock ownership before and after capture and transfer. Maintained source cannot enter the once-only role-recovery path. Two independent actual-copy restores prove both versions, unchanged complete logical data and authorization, clean restart, and rollback. The joint descriptor accepts either exact profile after its proof and cleanup pass. A dormant combined capture overlay preserves both runtime and startup-guard mounts. Native qualification of this new profile remains required.

No live-only edits, identity rotation, HBA weakening or storage migration.

Boundaries

No NAS writes, exports, restores or deletion. No Zot push, restart, deletion or garbage collection. No existing credential rotation. No replay of once-only PostgreSQL role recovery. Existing unrelated work and all original protected points remain intact. This spec grants no new authority; it implements the already approved Issue 103 scope.
