Scope and evidence

Issue103 CEPH_SECURITY includes native CephFS acceptance separately from RBD, controller generation and Rook orchestration. Reuse the disconnected, signed Fedora44 AMD64 kernel7.2.11/Ceph20.2.4 profile. Assumptions are explicit: fresh synthetic regular-file OSD, one loopback monitor/manager/MDS, one-replica synthetic pools, no availability or production recovery claim. Add the matching signed ceph-mds RPM through the existing complete hash/signature-checked repository solver. Production, NAS, hardware, CSI and SELinux container domains remain outside this prerequisite.

Exact20.2.4 MDS instructions define native keyring/configuration and daemon startup. Filesystem-scoped client capabilities separate the monitor, MDS and tagged data-pool grant. Kernel mounting requires an actual kernel mount. Mount options document secretfile, noshare and secure messenger mode. Keep synthetic credentials in private files/RAM; never put values in argv or retained logs.
