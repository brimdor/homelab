Issue 103 — Sporecast SELinux recovery

Status: planned repair; no application rollout accepted yet. Existing maintenance authority covers this software fault.

Evidence and objective

On October 27, Pikachu recorded 136,007 Sporecast file-lock AVCs. The current backend process uses s0:c599,c776; its RBD directory and SQLite database use s0:c317,c677. The historical actor that changed labels is UNKNOWN. Kubernetes readiness alone did not detect this failure.

Preserve the original backend digest, single RWO writer, database and retained historical files. Give the backend and its ordinary backup pod the same explicit MCS level so they can share their volume under enforcing SELinux. Keep separate application labels isolated. The NAS backup destination, schedule and command remain unchanged; no manual NAS backup is permitted.

Recovery contract

Extend metal/scripts/sporecast_recovery.py with an explicitly selected October 27 production profile. Keep the historical profile as the default, preserving old recovery verification. Bind the current Pod UID, container ID, PID/start time, machine/root identity, image, PVC/PV and native CSI device/inode before any freeze. Recheck Kubernetes storage ownership immediately before capture.

Reuse the existing pidfd freeze, independent resume watchdog, complete memory snapshot, framed protected transfer, WAL-aware isolated SQLite fingerprint and disconnected original-image restore. Read real data only from the identified Ceph mount. Store recovery on Pikachu's protected local ext4 recovery root, never on the NAS or workstation disposable storage.

Docker on Pikachu now enforces SELinux. Apply Docker's private :Z bind labeling only to the disposable isolated restore copy. Never mount or relabel the original protected recovery point or production data in the restore container. Preserve no-network, nonroot, read-only root filesystem, dropped capabilities and mandatory cleanup.

Acceptance and rollback

Require recovery integrity, foreign keys, complete typed logical fingerprints, original-image native readiness and cleanup. Require unchanged PVC/PV identities, expected original image, actual container_t confinement with matched MCS labels, successful SQLite lock acquisition under that process label, no new related AVCs, healthy endpoints and Argo Synced/Healthy. Preserve the old label failure as historical evidence.

Stop on changed identity, active backup writer, damaged framing, failed resume, restore discrepancy or unproven storage. Retain partial recovery material. Revert configuration through Git if needed; do not run an incompatible old database or delete data. A return to the mismatched random labels is not successful recovery.

Implementation boundaries

Use existing Python modules and explicit profiles; no new dependency or generic recovery framework. Example: select_profile('pikachu-20261027'). Keep historical defaults and refusal checks. No SELinux disablement, privileged production container, NAS operation, node upgrade, Strata promotion or image rebuild belongs to this patch.
