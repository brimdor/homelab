Isolation and exact procedure

  1. Use a new private nonsymlink operator-owned work directory outside the source checkout. Download only public verified media; keep all credentials, production records, kubeconfigs, recovery points, physical disks and host shares outside the VM. Reject image hash changes and external qcow backing files. Create one new overlay and synthetic login/host keys. Pin that exact fixture host public key before SSH; disable agent access, password login, global SSH configuration and connection multiplexing.
  2. Boot exactly one q35 AMD64 QEMU instance using software TCG emulation, two virtual CPUs and4GiB RAM. Media devices are read-only; only its owned overlay is writable. Bind the SSH forward exclusively to an ephemeral IPv4 loopback port. QEMU restrict=on disables guest routing to the host/outside except the explicit SSH forward. No bridge, shared directory, production device, production credential or guest egress is configured. Independently refuse successful guest connections to the API VIP or an external address.
  3. Use a CIDATA ISO and NoCloud configuration for the fixture user, pinned host key and hostname. Package refresh/upgrade stays disabled. Stop on an evidenced boot failure or SSH trust/authentication denial; preserve the failed result and fix the owning candidate. Do not weaken trust. Observe actual progress without an overall experiment deadline.
  4. Require Fedora44, AMD64, Python3.14 and the exact synthetic hostname. First execute an intentional Ansible preflight refusal and prove unchanged machine/filesystem/boot/kernel identities. It must fail before any target change. This exercises the actual controller/SSH/target Python boundary, not a mocked module.
  5. Mount the signed DVD inside the disposable VM only. Define a disabled-by-default file repository with GPG checking enabled. Bootstrap a missing libdnf5 binding exclusively from that repository. Execute the actual core2.21.5 DNF5 module for cronie, dnf5-plugins and dnf5-plugin-automatic; disable every other repository and automatic module dependency installation. Repeat installation and require idempotence. A missing package, signature or dependency is a finding; do not add an internet repository or skip the failing package.
  6. Exercise the installed systemd module against the fixture's dnf5-automatic.timer and hold it masked/stopped. Exercise the pinned posix sysctl module with a persistent synthetic setting. Perform one real guest reboot through Ansible; require a new boot ID, unchanged machine/root-filesystem/kernel/architecture identity, strict SSH continuity, a held timer and the persisted sysctl. Record exact package/kernel/OS/tool versions and module/task results.
  7. Finally stop and reap only this QEMU process and owned command children, remove its media/overlay/seed/synthetic keys/controller environment/archives/caches/logs, and verify exact paths/process absence. Retain only compact sanitized acceptance/failure and cleanup evidence. Preserve installed tools, source/Git, all production state and original recovery material.
