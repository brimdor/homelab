Combine native host maintenance with surviving cluster capacity

Remaining software boundary

The accepted actual API drain/scheduling/release profiles use synthetic host/package safety. The accepted native Fedora release profile used a direct driver, and the separate durable package-dispatch profile is still active. None establishes their full combined execution. Continue under existing Issue103 authority; production recovery, NAS restrictions and physical readiness remain separate gates.

Isolation design and research

Use three separately identified private Fedora VMs, with restricted user networking for their owned SSH/repository channel and a second private NIC for cluster traffic. Keep the two surviving nodes and the network process running while the target reboots. No host TAP, bridge, sudo, physical interface or production route is needed. The QEMU manual documents socket backends and hub ports. The QEMU socket implementation frames Ethernet with a network-order32-bit length and restores its listener after a client disconnects. Bind every listener explicitly to127.0.0.1. Local listeners are not an authentication boundary against other local processes.
