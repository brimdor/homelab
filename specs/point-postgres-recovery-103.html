Migration and acceptance gates

A successful17.11 restore proves exact-version recovery only. PostgreSQL18 requires a separately qualified exact maintained image, extension/locale compatibility, a tested dump/restore and data rollback path, fresh writer-quiesced backups, repository-owned writer suspension including scheduled consumers, canary rollout and actual application/schema/API acceptance. Never start18 against17 files or roll back an old engine against upgraded files. Preserve existing PVC identities and the untouched original datadir until acceptance. No production major upgrade is authorized by a restore receipt alone.

PostgreSQL18 release notes require a major-version migration and describe default checksums. pg_dump defines consistent native archives; pg_restore defines archive extraction and restore. Official image documentation describes18's changed PGDATA/volume convention. Review those contracts before any candidate deployment.
