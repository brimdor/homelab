Evidence and design assumptions

The existing helper binds an empty owned Docker VM, loopback-only API, non-production cluster UID, three synthetic k3s1.33.6 nodes and SHA256-verified Cilium charts. Reuse those checks without modifying the active bridge run. Use its synthetic172.31.240.0/24 Docker network; never use production10.0.20.224/27. An ordinary external Docker client on that bridge represents a same-L2 caller, not a physical VLAN, switch or Tailnet caller.

Official L2 guidance describes ARP ownership by one lease holder, interface selection, kube-proxy replacement and the incompatibility of externalTrafficPolicy Local. Official LB-IPAM guidance defines blocks and reserved boundary addresses. The existing source audit establishes blocks support in1.15.1 and cidrs removal in1.16.

Exact1.15.1 official LB-IPAM source contract nz3zwc2b identifies the older annotation name io.cilium/lb-ipam-ips, while the new documentation uses lbipam.cilium.io/ips. Use the explicitly supported single-address spec.loadBalancerIP across this bridge, preserving the requested VIP without assuming the newer annotation works on the baseline.

Objective and acceptance

  • Create the original cidrs pool on1.15.1 with boundary addresses reserved. Allocate a fixed synthetic VIP and prove normal HTTP service traffic.
  • Migrate cidrs to identical blocks with a JSON patch testing UID/resourceVersion/old CIDRs. Require unchanged pool UID and service VIP.
  • At baseline, every patched adjacent forward version, rollback and return, require three ready exact-version agents, the same pool and Service UIDs, original VIP and three ready backend endpoints.
  • From a client outside Kubernetes, send native raw ARP requests. Require exactly one unique responding MAC equal to the current lease holder's Docker interface MAC. Require the exact synthetic HTTP response.
  • Exclude the current holder through the synthetic policy's node label, require the same lease UID to move to another eligible node with increased transition count, repeat ARP/HTTP checks and restore eligibility.
  • Every required stage must produce its own receipt. Missing stages, ambiguous ARP, stale lease, wrong payload, version, UID or address fail. Retain failed evidence; do not skip it.
