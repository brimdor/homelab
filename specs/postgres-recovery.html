Export phase

Add a temporary Job, ConfigMap and two scoped policies through apps/postgres. Use the exact running PostgreSQL 17.5 digest, existing Secret references, UID99/GID100 and read-only transaction defaults. Allow the producer only DNS and the existing PostgreSQL Pod on5432; exclude sprigatito. Never mount production PGDATA or a PVC.

Exclusively create /mnt/user/postgres_backups/recovery-postgres-20261019, private owner markers and an empty restored/ subdirectory. Validate the reviewed catalog keyset, version, features and fresh capacity. Export with standard pg_dumpall --no-role-passwords --no-tablespaces --clean --if-exists. This writes destructive SQL as backup data; the producer never executes it. Passwords are omitted. Each database uses PostgreSQL's consistent logical export; cross-database atomicity is not claimed.

Compare source schema hashes and a password-free role/authorization fingerprint before and after export. Refuse changed definitions. Require a nonempty warning-free SQL export, strict checksums and a final completion marker. Preserve failed real recovery material. Real records, names, roles and raw diagnostics remain privately on NAS. Never copy them into Git, the Mac, issue bodies or disposable testing storage.

Restore phase

After successful producer verification, pin its exact manifest SHA256 through a second Git change. Replace the producer Job with an isolated verifier. Give it no production credentials, no network access, no Service or TCP listener. Mount the bundle read-only and only its dedicated restored/ subdirectory writable; other NAS data is unreachable through a writable mount. Use a private Unix socket and a new bootstrap role/control database whose absence from the source was verified.

Validate the pinned manifest, fixed safe filenames, regular nonsymlink files, ownership markers and checksums before SQL execution. Initialize a fresh cluster with page checksums, then restore with psql -X and ON_ERROR_STOP. Generated DROP/CREATE commands affect only this isolated cluster. Compare the six-database catalog, version/locale, schema hashes and role/authorization fingerprint. Exclude the deliberate bootstrap identity and role passwords from that fingerprint. Count actual restored relations/rows without exporting records.

Stop the owned server, verify shutdown and PID-file absence, then run offline pg_checksums --check. A complete SQL execution, schema/authorization comparisons and page checksums provide restore evidence. Do not claim live row counts equal a past dump under concurrent writes, byte-identical source records, application login or offsite recovery.

Other database servers, etcd, NAS/PVC recovery, role-password and application acceptance, offsite proof, SATA remediation and release/security gates remain.
