  6. On any regression stop the transition before another node; fix ordinary source/fixture errors through another validated publication. Preserve failed evidence. A caller-owned finally path removes exact helper/client/node containers, VM, images, downloaded binaries, synthetic snapshots, private kubeconfig, processes and scratch. Retain compact sanitized commands/results and cleanup receipts only.

Boundaries and limitations

Always: verify ownership immediately before every mutation; keep synthetic credentials inside private scratch/VM and never persist raw restore logs; use compatible kubectl clients, exact hashes and strict acceptance. Separate approval remains required: production disruption, active-data migration, actual security changes and protected application releases. Never: touch production nodes or NAS data, use a real kubeconfig in the fixture, weaken TLS/SELinux, retry the denied Fedora policy/package path, use host mounts, skip required failed cases, publish credentials or revoke the incident PAT before the final maintenance step.

A container restart kills that node's pod processes; it does not reproduce service-only restart continuity. Original container image metadata remains the pinned baseline while measured running binaries/runtime versions change. This fixture uses the container default snapshotter; production's declared stargz configuration remains unqualified. This fixture cannot certify Fedora 44 SELinux policy, production AMD64/GPU/CSI, physical networking/kube-vip, host boot/drain behavior, NAS backup recovery or the Sprigatito SATA incident. The separately accepted Cilium bridge remains necessary. A pass advances a prerequisite, leaves K3S_CILIUM open and does not make all six production layers GREEN.
