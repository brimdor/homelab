NFS_PROVISIONER_UPDATE: independent successor evaluation

Objective and scope

Evaluate the released Kubernetes NFS CSI driver4.13.5 as a maintained successor candidate. This is engineering within approved Issue103, independently reviewable without production NAS access. The current subdirectory provisioner and all five bound claims remain the source of truth. No discovered Argo chart, controller rollout or migration is introduced by this specification. Release activity is evidence of maintenance, not a vulnerability-free or production-compatibility claim.

Primary source contract

The released4.13.5 notes list security fixes. Its versioned README identifies GA and Kubernetes1.21+. This advertised floor alone does not validate every current sidecar on the actual cluster. The exact chart declares chart/application4.13.5. Do not use charts/latest or master configuration as the accepted candidate.

The versioned parameter contract supports existing NFSv3/v4 servers, dynamic subdirectories and static shares. Default deletion deletes data; nonzero mountPermissions can chmod, optional uid/gid can chown, and fsGroupPolicy File permits kubelet ownership changes. These behaviors require explicit synthetic acceptance and must not be exercised on the protected NAS. Snapshot archives also write to the NFS server.

Kubernetes1.33.6 ValidatePersistentVolumeUpdate rejects changing PersistentVolumeSource after creation. Consequently converting an existing spec.nfs PV to spec.csi cannot preserve that PV UID through an in-place patch. This candidate is not a drop-in identity-preserving update for the five retained bindings. Preserve the legacy provisioner for those bindings while evaluating a separate synthetic class. Any future migration needs a complete data/binding/recovery design and must satisfy the NAS restriction.
