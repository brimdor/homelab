Objective and evidence

Create a protected, hash-verified off-master recovery bundle and prove that the exact installed k3s version restores it, decrypts bootstrap material and serves the expected Kubernetes identity and encrypted data inside an isolated container. Leave the live masters, workload data and existing backups intact.

  • Trusted root SSH and the canonical inventory identify charmander 10.0.20.11 as source and pikachu 10.0.20.14 as off-master destination. Both are active inventory nodes.
  • Evidence etcd-recovery-metadata-78hknhrj/outputs/metadata.json records enabled AES-CBC encryption, matching server encryption hashes, snapshots and root-only token/configuration files on all three masters.
  • Evidence etcd-isolated-host-capabilities-1f56jgkd/outputs/capabilities.json records pikachu's k3s v1.33.6+k3s1, working Docker 24.0.5, no Docker containers and 33,164,058,624 available root-filesystem bytes. These observations do not prove a restore.

K3s requires the matching server token. Its restore procedure checks the snapshot, resets membership and extracts protected bootstrap material. Its agentless mode disables the embedded agent; this does not itself provide network isolation. An etcd-only restore cannot establish full k3s recovery.

Commands, structure and style

Planned operator interface: python3 metal/scripts/etcd_recovery.py qualify --run-id <unique-id>, then python3 metal/scripts/etcd_recovery.py copy --run-id <unique-id>, then python3 metal/scripts/etcd_recovery.py restore --run-id <same-id> --manifest-sha256 <verified-sha256>. Qualification uses synthetic data and must pass isolation and cleanup before a production bundle is consumed.

Tests belong in metal/scripts/test_etcd_recovery.py: python3 -B -m unittest discover -s metal/scripts -p test_etcd_recovery.py. Run scoped pre-commit and git diff --check. Local test routing follows the operator's external policy.

Use explicit failure and ordinary functions, consistent with repository recovery helpers: if destination.exists(): raise RuntimeError("refusing to overwrite recovery material"). Keep credentials in files or streams, never command arguments or emitted errors.
