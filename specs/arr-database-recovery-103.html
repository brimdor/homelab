  3. Warm only the selected database files through read-only file I/O before pausing. Re-read fresh identity afterwards. Require actual available RAM for the entire selected capture. Boundaries and rollback

Always protect original data and preserve failed evidence. Existing authorization covers independent database recovery work; no new approval gate is introduced here. Explicit application releases, provider actions, destructive data changes and production rollout gates remain separate. Never write NAS/NFS, trigger native backup endpoints, copy real data to disposable workstation storage, reset credentials, mount originals in a test container, downgrade live data or claim public login/media/offsite/all-PVC recovery proof. Capture rollback is unconditional exact-PID resumption; restore rollback is exact owned fixture cleanup. No production chart, Pod, volume or application configuration changes.
