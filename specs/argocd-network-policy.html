Argo CD repository ingress policy

Maintenance issue #103, task ARGO_NETWORK_POLICY, prerequisite to PR_REVIEW and CHART_MINOR_UPDATES.

Objective and evidence

Apply the official workaround for GHSA-47m3-95c7-g2g8 on chart 9.5.18. On October 19, 2026 UTC, argocd had no NetworkPolicies. A zero-payload TCP probe from the existing Radarr Pod reached repository RPC port 8081. This proves reachability, not exploitation. The issue authorizes separating security fixes from major upgrades.

Structure and style

Only system/argocd/values.yaml changes desired state. This specification records the contract. Use the installed chart's existing nested YAML schema:

argo-cd:
  global:
    networkPolicy:
      create: true

Boundaries and recovery

Always use repository-first GitOps and preserve unrelated edits. The chart policies restrict repository RPC and Redis to named Argo peers, allow metrics across namespaces, and leave server ingress unrestricted. They introduce neither egress restriction nor namespace-wide default deny. ApplicationSet and notification Pods remain unselected with the current chart settings.

Separate PR merge and release approvals still apply. Never deploy conflicted PR108, change chart/image versions, delete live policies, edit cluster workloads or trigger application writes as part of this task.

Validate controller-to-repository selectors before rollout to preserve Git recovery. If acceptance fails, stop dependent changes, record the exact fault, revert the exact policy commit in Git, validate, push master and verify reconciliation. A blocked Git recovery path requires reporting and diagnosis; it does not authorize live edits.
