Reproduction and boundaries

Select a separately owned virtual environment and collection directory; install requirements.txt with --require-hashes. Verify the collection lock and install only its exact archives with ansible-galaxy collection install --offline --no-deps. Set ANSIBLE_CONFIG to the maintenance configuration and ANSIBLE_COLLECTIONS_PATH to that owned directory. Route all local scratch/cache outputs through the operator's applicable storage policy. Never change HOME or existing credentials. Run the named safe fixture suite with the environment's Python and ansible-playbook on PATH; rerun the three syntax-only checks with an explicit inventory. Remove the owned environment and fixtures after its immediate consumer finishes.

This lock does not include the Python Kubernetes client: module discovery/syntax is accepted, Kubernetes-module execution is not qualified. No Fedora target module, DNF transaction, systemd/offline upgrade, reboot, GPU module, CSI behavior, native Linux controller or live SSH task has been tested here. The old broad bootstrap and destructive PXE entry points remain unsuitable for in-place upgrades. A1 still requires the dedicated one-host workflow, per-hop signed package/repository proof, isolated failure/resume/reboot checks, exact workload order and exercised recovery. Hardware/NAS/security gates apply only to their dependent execution.
