HumbleAI Canary activation contract

The IMMUTABLE_IMAGE_TAGS requirement in Issue103 applies to active workloads. This Canary deliberately declares zero replicas. Its missing canary image is not a running unpinned workload and must not be replaced with an arbitrary production or demo candidate.

Required desired state

Keep the current replica count, image declaration, hostnames, services, secrets and resources unchanged. The chart's values.schema.json accepts the explicit stopped state without an artifact. Any positive or omitted main-controller replica count requires main.containers.main.image.digest to be a complete lowercase sha256 digest. Missing, empty or malformed digests must fail rendering. An omitted count is not treated as zero because the dependency defaults to one.

This guard prevents normal Helm/Argo activation by mutable tag alone. Do not bypass schema validation. It does not prove a supplied digest exists, is approved, is compatible or is safe to run. A future release still requires the intended source/artifact, registry pullability, normal deployment review and application acceptance. No registry publication, new artifact, image pull, Pod activation or successful Canary application behavior is claimed by installing the guard.

Acceptance and rollback

Require identical before/after rendered Kubernetes resources at zero replicas. Exercise actual Helm rendering for the stopped state, missing replica count, positive counts with missing/empty/malformed digests, and a syntactically valid digest. Synthetic digest acceptance proves validation syntax only. After publication to canonical Gitea master, refresh the owning Argo Application and verify Synced/Healthy at that revision, unchanged Deployment/ReplicaSet identity and zero Pods.

Retain the dormant state and all NAS/protected Zot restrictions. Rolling back the guard must never activate the Canary or publish an image. Keep the original missing-manifest receipt; it remains a future-release limitation, not a fabricated artifact or an active-workload failure.

Supported mechanism

Helm values schemas apply to lint and template rendering. The guard uses standard draft7 required, anyOf, const and pattern constraints. JSON Schema composition defines the alternatives; the upstream app-template dependency retains its own validation.
