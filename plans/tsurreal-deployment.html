Private LoadBalancer policy correction

At 22:53 UTC on October 30, a single private-client TLS attempt produced Tsurreal-only Hubble ingress POLICY_DENIED events. Its observed source 10.0.9.39 is the CiliumInternalIP of the existing LoadBalancer forwarding node, confirmed through exact source-address mapping. Tsurreal's realized ingress policy contained only the LAN CIDR and automatic local-host exception. Cilium 1.20.4 policy documentation states that CIDR selectors exclude cluster node addresses by default and provides host/remote-node entities for node traffic. Add one namespace-scoped CiliumNetworkPolicy selecting only the Tsurreal Canary labels, permitting host and remote-node ingress only on TCP 8443. Retain the LAN CIDR policy, deny-all egress, private LoadBalancer, no NodePorts and no public route. This trusts the existing private node forwarding boundary; it does not authenticate the original client. Do not alter shared Cilium configuration or externalTrafficPolicy, which remains Cluster for the existing L2 design. Verify actual private HTTPS after reconciliation; an admitted policy alone is not a connectivity pass.
